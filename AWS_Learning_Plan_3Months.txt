------------------------------------------------------------------------------
THEORY (45 mins):
  [ ] What is Cloud Computing?
      - On-demand delivery of IT resources over the internet
      - Pay-as-you-go pricing (like electricity bill)
      - No need to buy/maintain physical servers
  
  [ ] Traditional IT vs Cloud Computing

      - No upfront cost (CapEx → OpEx)
      - Scalability (grow/shrink as needed)
      - Global reach (deploy worldwide in minutes)
      - High availability (always running)

DAY 2: Cloud Service Models (IaaS, PaaS, SaaS)
------------------------------------------------------------------------------
THEORY (45 mins):
  [ ] Three Cloud Service Models:

      ┌─────────────────────────────────────────────────────────┐
      │                    YOU MANAGE                           │
      ├─────────────────────────────────────────────────────────┤
      │                                                         │
      │  IaaS              PaaS              SaaS               │
      │  (Infrastructure)  (Platform)        (Software)         │
      │                                                         │
      │  ┌───────────┐    ┌───────────┐    ┌───────────┐       │
      │  │Application│    │Application│    │           │       │
      │  │   Data    │    │   Data    │    │           │       │
      │  │  Runtime  │    │           │    │   Cloud   │       │
      │  │ Middleware│    │   Cloud   │    │  Provider │       │
      │  ├───────────┤    │  Provider │    │  Manages  │       │
      │  │    O/S    │    │  Manages  │    │Everything │       │
      │  │Virtualize │    │   Below   │    │           │       │
      │  │  Servers  │    │           │    │           │       │
      │  │  Storage  │    │           │    │           │       │
      │  │ Networking│    │           │    │           │       │
      │  └───────────┘    └───────────┘    └───────────┘       │
      │     AWS EC2        AWS Elastic       Gmail             │
      │                    Beanstalk         Salesforce        │
      │                                      Dropbox           │
      └─────────────────────────────────────────────────────────┘

  [ ] IaaS (Infrastructure as a Service)
      - You rent: servers, storage, networking
      - You manage: OS, applications, data
      - Example: AWS EC2, Azure VMs
      - Analogy: Renting an empty apartment

  [ ] PaaS (Platform as a Service)
      - You get: ready platform to deploy apps
      - You manage: only your application and data
      - Example: AWS Elastic Beanstalk, Heroku
      - Analogy: Renting a furnished apartment

  [ ] SaaS (Software as a Service)
      - You get: complete software ready to use
      - You manage: nothing (just use it)
      - Example: Gmail, Salesforce, Zoom
      - Analogy: Staying in a hotel

DAY 8: Introduction to IAM
------------------------------------------------------------------------------
THEORY (45 mins):
  [ ] What is IAM?
      - Identity and Access Management
      - Controls WHO can access WHAT in your AWS account
      - FREE service (no charges)
      - GLOBAL service (not region-specific)

  [ ] Why IAM is Important?
      - Security: Don't share root account
      - Control: Give minimum permissions needed
      - Audit: Track who did what

  [ ] IAM Components:
      
      ┌─────────────────────────────────────────────────────────┐
      │                      IAM COMPONENTS                     │
      ├─────────────────────────────────────────────────────────┤
      │                                                         │
      │  USERS                                                  │
      │  └── Individual people or services                     │
      │      Example: john@company.com                         │
      │                                                         │
      │  GROUPS                                                 │
      │  └── Collection of users                               │
      │      Example: Developers, Testers, Admins              │
      │                                                         │
      │  ROLES                                                  │
      │  └── Temporary permissions for services/users          │
      │      Example: EC2 accessing S3                         │
      │                                                         │
      │  POLICIES                                               │
      │  └── JSON documents defining permissions               │
      │      Example: Allow read-only access to S3             │
      │                                                         │
      └─────────────────────────────────────────────────────────┘

  [ ] Root User vs IAM User
      ROOT USER:
      - Created when you create AWS account
      - Has FULL access to everything
      - Should NOT be used for daily tasks
      - Use only for: billing, account settings

      IAM USER:
      - Created inside AWS account
      - Has only permissions you assign
      - Use for daily work
      - Each person should have their own IAM user

DAY 10: IAM Policies Deep Dive
------------------------------------------------------------------------------
THEORY (45 mins):
  [ ] What is an IAM Policy?
      - JSON document that defines permissions
      - Specifies: What actions are allowed/denied on which resources

  [ ] Policy Structure:
      ```json
      {
        "Version": "2012-10-17",
        "Statement": [
          {
            "Effect": "Allow",          // Allow or Deny
            "Action": "s3:GetObject",   // What action
            "Resource": "arn:aws:s3:::my-bucket/*"  // On what
          }
        ]
      }
      ```

  [ ] Policy Types:
      - AWS Managed Policies: Pre-built by AWS (recommended to start)
      - Customer Managed Policies: You create and manage
      - Inline Policies: Embedded in user/group/role (not recommended)

  [ ] Common AWS Managed Policies:
      - AdministratorAccess: Full access to everything
      - PowerUserAccess: Full access except IAM
      - ReadOnlyAccess: View only, no changes
      - AmazonS3FullAccess: Full access to S3
      - AmazonEC2FullAccess: Full access to EC2

HANDS-ON (45 mins):
  [ ] Task 1: Explore Existing Policies
      - Go to: IAM → Policies
      - Search: "S3"
      - Click on "AmazonS3ReadOnlyAccess"
      - Click "JSON" tab to see the policy document
      - Understand what it allows

  [ ] Task 2: Create Custom Policy
      - Go to: IAM → Policies → Create policy
      - Click "JSON" tab
      - Paste this policy:
        ```json
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Effect": "Allow",
              "Action": [
                "s3:ListBucket",
                "s3:GetObject"
              ],
              "Resource": "*"
            }
          ]
        }
        ```
      - Click Next
      - Policy name: "MyS3ReadPolicy"
      - Create policy

DAY 11: IAM Roles
------------------------------------------------------------------------------
THEORY (45 mins):
  [ ] What is an IAM Role?
      - An identity with permissions (like a user)
      - BUT: Not associated with a specific person
      - Can be "assumed" by anyone/anything that needs it
      - Temporary credentials (auto-rotate)

  [ ] When to Use Roles?
      - EC2 instance needs to access S3
      - Lambda function needs to access DynamoDB
      - Cross-account access
      - Federated users (SSO)

  [ ] Role vs User:
      USER                          ROLE
      - For people                  - For services/applications
      - Long-term credentials       - Temporary credentials
      - Username/password           - Assumed when needed
      - Belongs to one person       - Can be used by many

HANDS-ON (45 mins):

      - Click Next

      - Create role

  [ ] Task 2: Explore Role Details
      - Click on the role you created
      - Note the ARN (Amazon Resource Name)

      ┌─────────────────────────────────────────────────────────┐
      │              IAM SECURITY BEST PRACTICES                │
      ├─────────────────────────────────────────────────────────┤

DAY 17: Connect to EC2 via SSH
------------------------------------------------------------------------------
THEORY (15 mins):
  [ ] What is SSH?
      - Secure Shell
      - Way to connect to remote servers securely
      - Uses key pair authentication
      - Default port: 22

HANDS-ON - Windows Users (60 mins):
  [ ] Option 1: EC2 Instance Connect (Easiest!)
      - Go to: EC2 → Instances
      - Select your instance
      - Click "Connect"
      - Choose "EC2 Instance Connect"
      - Click "Connect"

  [ ] Option 2: Using PowerShell
      - Open PowerShell

DAY 19: Security Groups (EC2 Firewall)
------------------------------------------------------------------------------
THEORY (30 mins):
  [ ] What is a Security Group?
      - Virtual firewall for EC2 instances
      - Controls inbound and outbound traffic
      - Rules based on:
        * Protocol (TCP, UDP, ICMP)
        * Port number (22, 80, 443, etc.)
        * Source/Destination (IP address or another security group)

  [ ] Security Group Rules:
      INBOUND (traffic coming IN):
      - SSH (22): For remote access
      - HTTP (80): For web traffic
      - HTTPS (443): For secure web traffic
      - Custom: Your application ports

      OUTBOUND (traffic going OUT):
      - By default: All traffic allowed
      - Can restrict if needed

  [ ] Security Group Behavior:
      - Stateful: If you allow inbound, response is automatically allowed
      - No "Deny" rules - only "Allow"
      - All inbound blocked by default
      - All outbound allowed by default
      - Changes take effect immediately

------------------------------------------------------------------------------
THEORY (60 mins):
  [ ] What is S3?
      - Simple Storage Service
      - Object storage (not file system, not block storage)
      - Store unlimited data
      - Highly durable (99.999999999% - 11 nines!)
      - Access from anywhere via URL

  [ ] S3 Concepts:
      
      ┌─────────────────────────────────────────────────────────┐
      │                     S3 STRUCTURE                        │
      ├─────────────────────────────────────────────────────────┤
      │                                                         │
      │  BUCKET                                                 │
      │  └── Container for objects                             │
      │      - Globally unique name                            │
      │      - Created in a specific region                    │
      │      - Example: my-company-photos-2024                 │
      │                                                         │
      │  OBJECT                                                 │
      │  └── File + metadata                                   │
      │      - Key (name): folder/subfolder/file.txt           │
      │      - Value (data): actual file content               │
      │      - Metadata: content-type, modified date           │
      │      - Max size: 5 TB per object                       │
      │                                                         │
      │  KEY                                                    │
      │  └── Unique identifier for object in bucket            │
      │      - Full path: photos/2024/january/img001.jpg       │
      │                                                         │
      └─────────────────────────────────────────────────────────┘

  [ ] S3 Use Cases:

  [ ] S3 Pricing:
      - Storage: per GB per month
      - Requests: per 1000 requests
      - Data transfer: out to internet
